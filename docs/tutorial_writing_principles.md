# 教程写作原则（第二轮）

> Phase 2 产物，配套《第二轮全书审计》（`docs/beginner_system_audit_v2.md`）。
> 适用范围：`chapters/` 下全部正文与阅读路线。**后续每一处改动都应能引用本文件的一条规则。**
> 目的：把“帮零基础读者建立系统认知”从口号变成可执行的判断标准。

## 0. 总纲

**系统关系 > 知识数量　直觉理解 > 完整推导　正确长期心智模型 > 暂时的绝对简化　问题驱动 > 术语堆积　一张稳定地图 > 多套分类。**

## 1. 唯一系统架构

- canonical = 第 1 章 1.3 的**六层功能链**（任务与智能／行为与技能／运动与规划／实时控制／驱动与嵌入式／机械执行）+ **横向基础设施**（中间件、算力、安全、数据与日志、仿真、配置模型标定）。
- 每一节开头保留「在整机里的位置」块引用并指向 1.3；新增节照做。
- **禁止**再引入并行分层。需要提旧称（机械与本体层、小脑层、大脑层……）时，写成“俗称／比喻”并回指 1.3。

## 2. “大脑 / 小脑”的使用规则

| 允许 | 必须 | 禁止 |
| --- | --- | --- |
| 章标题、开场、口语化复述里作为轻松比喻 | 正文第一次出现时补一句“这是教学比喻，正式分层见 1.3” | 当层名用于分类判断（“X 属于大脑层”）；据此推断“AI = 大脑、传统控制 = 小脑” |

替代写法：说**层级**用功能链的名字；说**方法**用“模型驱动／优化／学习／大模型”。两者的关系见 5.1 的 4×4 矩阵。

## 3. 强结论的使用规则

出现「一定／都是／只／只能／永远／不会／必须／就是／所有机器人／一般都／本质上就是」时，先判类型：

| 类型 | 处理 | 例子 |
| --- | --- | --- |
| **A 数学或物理事实** | 保留强结论 | “关节力矩必须平衡” |
| **B 定义** | 可明确表达 | “自由度是描述构型所需的最少独立变量数” |
| **C 常见工程实现** | **必须加限定** | ✗“真机不训练” → ✓“大多数部署阶段以推理为主，训练通常在离线完成” |
| **D 当前研究趋势** | **必须标注时间性** | ✓“当前常见”“仍在快速演进”“尚未统一” |

判定口诀：**换一台机器人还成立吗？** 只对某类实现成立的就是 C；只对当下成立的，就是 D。

## 4. 术语解释顺序：先问题，后名字

```
现象 → 问题 → 为什么现有模块解决不了 → 引入概念 → 名称（中英对照）
     → 输入／输出 → 在整机哪里 → 在 G1 上长什么样 → 需要深入时再讲算法
```

- 术语段**不要**用“XX 是……”开头（数学定义类节除外）。
- 正例（状态估计）：“IMU、编码器、足底力都在发数据，但没有任何一个传感器直接告诉你‘身体朝哪、速度多快、哪只脚在支撑’——把这些测量拼成机器人当前状态，就是状态估计。”
- 目标是让读者反复获得“**原来这个词就是解决这个问题的**”的瞬间。

## 5. 三层阅读深度与安全退出点

| 层 | 时长 | 内容 |
| --- | --- | --- |
| Layer 1 | 30 秒 | 一句直觉（“IK = 已知手要去哪，反推关节怎么转”） |
| Layer 2 | 5–10 分钟 | 为什么需要／输入输出／上下游／在整机哪里／G1 落点 |
| Layer 3 | 深入 | 数学、算法、特殊情况、工程细节、SDK、论文 |

- **安全退出点**：篇幅 > 4,000 汉字，或含 ≥2 个公式块的节，必须在第一段深入内容前显式提示：

  > **第一次阅读如果只是建立系统概念，到这里即可。下面……属于……深入内容。**

- 标记词统一为「可跳过／进阶／查阅」，判断标准统一指向《在校学生阅读路线》的“先读什么、什么可以以后再看”。

## 6. 每节结尾的“能力解锁”

格式：

> **到这里，你应该已经能听懂：**“……”

- 引号里必须是**读者能听懂的真实会议用语**（别人的输出），不是知识复述；
- 每节一条，不与正文重复；例：“Planner 给末端目标，IK 解成 joint target。”

## 7. 按节类型选择叙事（不强套模板）

| 类型 | 代表节 | 该回答的核心问题 |
| --- | --- | --- |
| 运行时模块 | 感知、状态估计、规划、控制 | 输入 → 处理 → 输出 → 谁给我、谁用我 |
| 数学／模型 | 4.1、运动学、动力学、雅可比 | 它描述什么关系？谁会用它？ |
| 物理子系统 | 执行器、传感器、电源 | 它在真实机器人里是什么东西？ |
| 开发工具 | ROS 2、URDF、Git、仿真 | 它在开发流程的哪一步用？ |
| 训练／生命周期 | 遥操作、数据集、训练、评测、部署 | 它处在生命周期哪个阶段？ |
| 研究范式 | VLA、WAM、世界模型 | 它想解决传统方法的什么限制？ |

无论哪种骨架，三条必须保留：**「在整机里的位置」+ 至少一条「一句话听懂」+ 参考资料**。

## 8. G1 使用规则

- 结构：通用概念 → 回到 G1（它长什么样）→ 换机器人哪些会不同 → 哪些原则不变。
- G1 是**可核对的落点**，不是要背的参数表：每条 G1 事实都要有可点开的来源；参数不要求记忆。
- 每节最多一个小节讲 G1；SDK 字段、关节编号不进主线（放附录或标注“查阅”）。

## 9. 前沿内容规则

- 定位：**打开窗户**，不做综述；结构：传统方法 → 遇到什么问题 → 新方法改变什么 → 目前发展到哪里。
- 标注时间性：WAM 等 2025–2026 仍在成形的方向，要写明“这是仍在快速形成中的研究方向与术语体系”。
- **禁止**把前沿范式与 Sensor／State Estimation／IK／Control 并列成“一台机器人必备模块”。
- 统一用三层标签：**基础必备／现代常用／研究前沿**（定义见《在校学生阅读路线》）。

## 10. 图示规范

- 一张图只表达一个关系；节点 ≤ 10；不追求完整 UML；目标是形成心智模型，不是展示系统有多复杂。
- 优先画图：数据流、控制流、传感器反馈、多时间尺度、算力拓扑、训练 vs 运行时、导航链、任务→技能→运动→控制、数据飞轮、VLA 的动作表示。
- 技术约定：纯 SVG + CSS／SMIL，无外部依赖；遵循 `prefers-reduced-motion`；组件内禁止 `setAttribute("class", …)`（会抹掉 Astro 作用域类，用 `classList`）；
  画布宽度对齐正文列宽（约 720px，按 1:1 渲染——画布越宽，字被缩得越小）。

## 11. 语言风格

- 保留：简洁、直接、工程现场感；“为什么？”“那问题来了”“回到 G1”“第一遍先记这一点就够了”“注意，这里很容易产生一个误解”。
- 禁止：强行幽默、网络段子化、过度拟人、每段感叹、为口语牺牲准确性。
- 同义压缩句配额：同一节里「一句话听懂／本质上／换句话说／简单来说」不要重复出现（择一即可）。

## 12. 做减法优先

优先删：重复解释、过度细节、同一术语多次定义、参数堆砌、第一遍不需要的公式、不影响系统认知的历史信息、模型罗列、并行架构表述。

判断标准：**删掉这一段，读者会不会失去知识？** 如果只是少读一遍同样的话，删。

## 13. 改动流程（强制）

1. 改前先查本文件对应条目，在提交信息里写明依据；
2. 改后至少跑：构建、站内链接、加粗解析、表格残片、产品导读校验；
3. 涉及删内容时，同步检查**引用它的话是否还成立**（曾出现“某节说‘前面讲过 X’，而 X 已被删”）；
4. 新增/移动小节后，检查附录 A 是否应收录该术语、阅读路线的时长与依赖是否要同步。
