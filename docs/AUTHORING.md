# 写作与配图规范（贡献者用）

面向读者的说明见仓库根 [README.md](../README.md)；这里记录这本书的编写标准，改稿、加节、补图前请先读一遍。

## 读者与定位

本书是一张“具身领域词汇地图”，不展开完整的机器人学推导。读者是刚进入具身智能 / 人形机器人 / 机器人 AI 的人：结构、电气与嵌入式、算法与软件从业者，以及需要听懂技术讨论的产品与 PR。

目标是**建立共同语言和系统级直觉**，不要求读者读完后能独立完成双足行走、强化学习训练或真实硬件部署。

## 写作原则

- 先讲人话，再给英文术语、缩写和公式；
- 每个专业词首次出现时同时给出规范英文表达；有常用缩写时一并标注；
- 介绍任何概念前，先用一个真实工程现象或现场问题引入；
- 每个词至少回答“它是什么、解决什么问题、在系统哪一层”；
- 用最少的数学解释关键关系，不用推导堆砌篇幅；
- 每个概念尽量连到一个真实工程接口或 G1 模型参数；
- 明确区分理论模型、仿真近似和真实机器人行为；
- 重点训练跨专业沟通，而不是让读者立刻成为某一方向的专家。

## 概念讲解模板

每节按固定顺序展开：

1. **先出现一个工程现象**：让读者看到“哪里不对”；
2. **还原现场提问**：用工程师真会说的话；
3. **给出术语名称**：规范英文表达与常用缩写；
4. **用直觉解释原因**：先讲机构、信号或系统行为，再给公式；
5. **连接上下游影响**：机械、电气、算法、软件分别要注意什么；
6. **落到 G1**：对应的模型、关节、消息或仿真现象；
7. **交叉验证并引用**：编号引用写在对应位置，节末列参考资料。

例：写“死点”时不能从雅可比矩阵开始，而要先写现场——关节还在输出、连杆却几乎不动，算法同学问“为什么这个位置程序会报错”；先给机械答案（四连杆接近共线，传动能力下降），再连到算法语言（同一位置雅可比接近奇异），最后说它如何影响限位、轨迹与安全。

## 术语与结论句体例（硬指标）

- 每节开头是**现场问题**（一段真实场景 + 一句被引用的提问），节末是**参考资料**；
- 每个术语级 H3 结尾有且只有一条加粗的 **一句话听懂**，用大白话复述该术语；与上一段并排看若删掉不影响理解，说明是复述，要重写；
- 全节第一条“一句话听懂”必须落在正文前 1200 汉字内（这是三篇导读“读到第一条一句话听懂”可执行的前提）；
- 引语与强调用全角 `“”`；`「」` 只用于指代小节名；正文里含中文的 ASCII 引号对必须为 0；
- 代码字面值、报错串、文件名用反引号，不要换成全角引号。

## 引用与交叉验证

- 资料优先级：教材与专著 → 同行评审论文/会议 → 标准与官方技术文档 → 厂商官方资料 → 维护良好的开源项目文档；论坛、博客、二手转载只能作线索；
- 重要术语尽量用两类以上相互独立的资料比对；资料间定义不一致时，在正文说明差异；
- 正文用顺序编号引用；引用必须能直接支撑对应的定义、公式或事实，不堆链接；
- G1 的型号、DoF、关节名、接口字段与模型行为必须与实际资料一致，不得凭印象写数字。

## 配图规范

遇到仅靠文字难以建立空间关系、信号流或因果关系的内容必须配图；能用表格或一段话说清的就不配图。优先配图场景：整机层级与数据流、连杆/关节/死点/坐标系、电机-减速器-驱动器-控制环、电源树与通信拓扑、传感器安装与坐标变换、受力与接触关系、ROS 2 节点与 TF、G1 三种模型变体、VLA/WAM 链路。

做法要求：

- **优先自制矢量图**：自包含 SVG（无外链字体、无外部位图、无 emoji），深浅色主题都能显示；
- **实拍与真实数据图**：实拍必须有明确许可，署名与许可要求**逐张**写进该节的参考资料，并在 [docs/IMAGE_DESIGN_NOTES.md](./IMAGE_DESIGN_NOTES.md) 留台账；数据图要写明数据来源与处理流程；
- **不伪造**：概念示意图不得伪装成 G1 的真实结构图；涉及 G1 的图必须注明用的是无手、锁腰还是带手模型；
- **图内文字**：主标注与正文同量级，缩到 720 px 宽仍清晰可读。

图片素材的接收、暂存与台账记录方式见 [docs/IMAGE_DESIGN_NOTES.md](./IMAGE_DESIGN_NOTES.md)。

## 贯穿案例：Unitree G1

| 使用场景 | 模型约定 |
| --- | --- |
| 系统总览、机械、电气、嵌入式 | `g1_29dof` 无灵巧手 |
| 运动学、动力学、平衡、控制 | 无手模型；腰部按展示需求选择锁定或非锁定 |
| ROS 2、DDS、低层控制 | 无手模型对应的 SDK / 消息接口 |
| 操作、双臂、灵巧手 | `g1_29dof_with_hand`，并注明具体手型 |
| VLA、WAM、视觉操作、模仿学习 | 带手模型，并明确 Dex1、Dex3、Inspire 等手型 |

每个涉及 G1 的小节要注明：模型文件、DoF、是否带手、腰部状态、URDF/MJCF、仿真器、关节顺序与坐标系约定。腰部锁定必须说明是使用官方锁腰模型，还是对模型做了 fixed/约束修改。

模型资产在 [`robot_descriptions/g1/`](../robot_descriptions/g1/)，来源与许可见 [`SOURCE.md`](../robot_descriptions/g1/SOURCE.md)；第三方代码与网格见 [`third_party/README.md`](../third_party/README.md)。

## 已定裁决（改稿时不要推翻）

以下结论来自多轮教学、领域与语言审计，改稿时按此执行；确有更好方案请先讨论再动。

- **章节顺序不动**。小节之间的衔接问题用“加一句桥接”解决，不搬家；复用小节名统一。
- **术语体例**：首次成文处给「中文名（English）」；代码字面值、报错串、文件名一律用反引号。
- **引号体例**：引语与强调用全角 `“”`；`「」` 只用于指代小节名；正文里含中文的 ASCII 引号对必须为 0。
- **结论句**：每个术语级 H3 结尾有且只有一条 **一句话听懂**；全节第一条落在正文前 1200 汉字内。
- **复用前文术语**（如摩擦锥、状态估计）：写回指“见 x.y 节”并给一句回顾，不重复整段定义，也不重复嵌入同一个交互组件。
- **“力矩”与“扭矩”**：机械章用“力矩”，电气章讲降扭矩/温升降额时用“扭矩”，两处不要互相改。
- **破折号节制**：解释说明、同位语可用；提示语后接解释改冒号，补评语改句号。同一句里不要出现两个以上。
- **长短标题**：导读用短标题（如“4.4 状态估计”），正文 H1 用完整标题——这是刻意的，不算不一致。
- **组件脚本只增删 class**（`classList`），禁止 `setAttribute("class", …)`：那会抹掉 Astro 作用域类，样式整体失配（曾导致力封闭演示的摩擦锥渲染成黑色）。
- **数字要能复算**：导读里的节数、时长、条数必须与正文和首页一致；不写会随改稿过期的计数。
