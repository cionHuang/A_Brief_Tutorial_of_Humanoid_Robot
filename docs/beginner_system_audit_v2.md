> Phase 1 产物，配套 Phase 2 的《写作原则》（`docs/tutorial_writing_principles.md`）。

## 2. 跨章问题（本轮重点）

### 2.1 六类高风险认知：逐条核实原文

| # | 位置 | 原文（节选） | 判断 | 处置 |
| --- | --- | --- | --- | --- |
| ① | 1.3「在线运行与离线开发」 | “真机运行时**不训练**，也没有 reward” | **C/D 类过强**：把常规部署写成普遍定律 | 改为“大多数部署阶段以推理为主，训练通常在离线完成；在线学习、在线适应与真机 RL 也是存在的模式”，reward 同理 |
| ② | 5.6「VLA 不承担毫秒级闭环」 | “VLA 做任务理解和动作决策，不做实时控制” | **基本准确**：这是频率边界，且同节已列动作表示（离散 token／连续回归／扩散流匹配）与动作粒度（技能调用／末端增量／关节动作） | 只把主语限定为“本教程讨论的这类低频 VLA”，不动结构 |
| ③ | 5.5「部署之后」一段的结论句 | “学习策略只负责‘关节目标往哪走’” | **C 类过强**：该句取自 `unitree_rl_gym` 这一个例子，但结论句写成了普遍规律 | 限定为“这个例子里”，并补一句：学习策略的输出粒度可以更低（残差、力矩），代价是安全与限幅责任更大 |
| ④ | 5.1「表示：token 与嵌入」 | “模型不直接处理图像、语言和关节角，而是先把它们切成 token”；结论句“token 是把图像、语言、动作切成模型能吃的小块” | **C 类过强**：语言与图像常切成 token，但状态与动作可以是连续嵌入／连续回归 | 改为“语言和图像常切成 token；关节状态与动作既可以是连续向量，也可以离散成 token，取决于表示选择” |
| ⑤ | 6.1「ROS 2 与实时」 | “**边界：毫秒级闭环不放在 ROS 2 里跑。**”；“每个模块是一个独立进程（节点，Node）” | **C 类过强**：真正的原因是普通回调没有最坏执行时间保证，而不是 ROS 2 本身不行；节点也不必然等于进程 | 改为“普通回调不适合做硬实时控制环；高频控制通常要专门实时线程、`ros2_control` 实时循环、共享内存或底层 SDK”，并补“节点是逻辑计算单元，不一定等于独立进程” |
| ⑥ | 4.6「零力矩点」 | “真正持续有效的判据是零力矩点（ZMP）”；“只要……ZMP 还在支撑域内……不会翻倒” | **C 类过强**：ZMP 是在平面接触、点足等假设下的经典工具之一 | 加前提与边界：ZMP 是经典双足在特定接触与平面假设下的重要工具；现代系统还会看质心动量、接触力可行性、摩擦与全身约束（本节已有质心动量与 WBC 约束，缺的是这句“只是一件工具”） |

### 2.3 模板化语言与叙事多样性

- 「一句话听懂」318 处，33 节都有「先看一个现场问题」——统一人格已经建立，但**每节都走同一套模板**：现场问题 → 术语 → 一句话听懂 → 上下游 → G1 落地。
- 「本质上」2 处、「换句话说」2 处、「简单来说」0 处——此前清理过一轮，措辞层面已不严重。
- 真正的问题是**结构层面**的重复感：数学/模型类、物理子系统类、开发工具类、研究范式类节都用同一个骨架，读者到第 3 章以后会产生“又是这一套”的疲劳。
- 目标第三、九、十六、十七条要求：按节类型选择叙事（运行时模块 / 数学模型 / 物理子系统 / 开发工具 / 训练生命周期 / 研究范式），并允许不同类型的开场。

## 3. 第 1 章逐节卡片（自查）

### 1.1 我们到底在研究什么：具身智能与人形机器人

- **希望新人带走**：具身智能 = 一个身体 + 自己转的感知—行动环；为什么用人形做教具。
- **服务系统认知**：是（划定对象）。**认知负担**：低。
- **过强结论**：无明显问题（上轮已把“三条判据”改成“自主程度不同”）。
- **重复**：无。**生动性**：弹幕开场有现场感。**问题链**：结尾指向“由什么组成／怎么运行”。
- **心智模型风险**：低。

### 1.2 一台人形机器人里面有什么

- **希望新人带走**：拆开一台 G1 有哪些部分；位置分区与功能分层是两刀。
- **服务系统认知**：是（物质基础）。**认知负担**：低（上轮已砍掉变体表、SDK 注释）。
- **过强结论**：无明显问题。**问题链**：结尾“四个专业四张图”自然引出 1.3。
- **心智模型风险**：低（已显式说明“四区 ≠ 六层”）。

### 1.3 从任务到电机：一台现代人形机器人如何运行

- **希望新人带走**：唯一总图（六层 + 两条链 + 横向基础设施 + 多速率 + 在线/离线）。
- **服务系统认知**：是（全书锚点）。**认知负担**：中（信息密度高，但有总图与表格支撑）。
- **过强结论**：**①“真机不训练、也没有 reward”**（见 §2.1）。
- **重复**：“闭环”一词承载三种含义，已在文中显式区分 ✓。
- **安全退出点**：不需要（本章是骨架，篇幅 2.6k）。
- **心智模型风险**：中→低。修掉 ① 后，剩余风险是读者把“典型架构”当成唯一方案——文中已两次声明“典型、不是唯一答案” ✓。
