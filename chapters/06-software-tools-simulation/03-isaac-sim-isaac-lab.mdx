## 先看一个现场问题

用单机 MuJoCo 训 G1 行走策略，一晚上只跑了几千万步，收敛遥遥无期；换到 Isaac Lab 开了 4096 个并行环境，训练吞吐上来了，但训出的策略回 MuJoCo 做 Sim2Sim 验证时直接摔倒。想加相机做视觉在环训练，一开 RTX（实时光线追踪）渲染，环境吞吐掉了一半以上。还有人把 URDF 直接导入 Isaac Sim，机器人加载出来了，关节方向和惯量却和官方 MJCF 对不上。

现场通常会这样问：

> “并行几千个环境到底图什么？同一个 G1，为什么换个仿真器策略就失效？开相机为什么会让训练变慢这么多？”

这四个现象在本节各有回收点：一晚上几千万步不够用，对应“并行训练”里 GPU 并行 rollout 的吞吐来源；Isaac 训练的策略回 MuJoCo 摔倒，对应“并行训练的代价与边界”与“什么时候用 Isaac、什么时候不用”两节；开相机吞吐掉一半，对应“传感器与渲染”里 RTX 渲染的代价；URDF 导入后关节方向与惯量对不上，对应“从 URDF/MJCF 到 USD”里的核对清单。

> **一句话听懂**：本节要回答的是并行为什么快、换仿真器为什么失效、代价从哪来；开头的四个现象都能在后面各节找到自己的回收点。

## 两个东西、两种角色：Isaac Sim 与 Isaac Lab

Isaac Sim 是 NVIDIA 基于 Omniverse（NVIDIA 的仿真与协作平台底座）构建的 GPU 高保真仿真平台，负责物理仿真（引擎是 PhysX 一类 GPU 物理引擎）、RTX 光线追踪渲染、传感器模拟、URDF/MJCF 导入器，以及 USD 场景格式。[4][5] Isaac Lab 是跑在它之上的机器人学习框架，负责把强化学习任务拆成 Manager 化环境、在 GPU 上并行训练、接入策略。

一句话说清分工：**Isaac Sim 提供平台，Isaac Lab 提供跑在这个平台上的学习流程。** 本节后续每一节都会标出自己属于哪一侧。它和 6.2 节 MuJoCo 的分工也可以一句话说清：MuJoCo 擅长单机精确的接触仿真与部署验证，Isaac 系列擅长数千环境并行的强化学习训练和视觉在环（Vision-in-the-Loop）训练。

> **一句话听懂**：Isaac Sim 是 GPU 仿真平台（物理、渲染、传感器、导入器、USD），Isaac Lab 是跑在它上面的学习流程（Manager 环境、并行训练、策略接入）；两者是平台和使用者的关系。

## 先看全局：一次训练要经过哪几段

一次从零开始的训练，链路只有五段：

```text
导入资产（Sim：URDF/MJCF Importer）→ 组装场景（Sim：USD 分层组合）
→ 并行环境（Lab：GPU 上数千环境）→ 策略训练（Lab：PPO）
→ 验证关口（MuJoCo 做 Sim2Sim → 实机，见 6.2 节）
```

后面几节就挂在这条链上：“USD 与资产”对应前两段（导入资产、组装场景），“Isaac Lab 的强化学习环境”对应中间两段（并行环境、策略训练），“什么时候用 Isaac、什么时候不用”决定这条链值不值得走；最后一段验证关口不归 Isaac，交给 6.2 节 MuJoCo 与随后的实机流程。

> **一句话听懂**：导入资产 → 组装场景（Sim）→ 并行环境 → 策略训练（Lab）→ MuJoCo 与实机验证；后面每一节都挂在这条链的某一段上。

## USD 与资产（Isaac Sim 侧）

### USD 场景描述

Isaac Sim 的场景格式是 USD（Universal Scene Description）：一种支持分层、引用和组合的场景描述系统，场景中的元素称为 Prim，整个场景称为 Stage。[1] 对机器人工程师而言，USD 最实际的特性是组合（Composition）：机器人、环境、传感器可以各自是独立资产，按层叠加成最终场景，改一层不动其他层。

> **一句话听懂**：USD 是 Sim 侧的场景格式，Prim 是场景里的元素、Stage 是整个场景；组合让机器人、环境、传感器分层叠加，各改各的。

### 从 URDF/MJCF 到 USD

G1 进入 Isaac Sim 走导入器：URDF Importer 或 MJCF Importer 把模型转换成 USD 资产。转换不是无损的，导入后必须逐项核对：关节轴线与正负方向、限位、惯量参数、碰撞网格、执行器增益。开头“关节方向和惯量对不上”，多数发生在这一步——不同导入器版本对 URDF 关节约定和网格缩放的处理有差异。核对的标准答案永远是从官方源文件（2.5 节、6.2 节）重新计算，而不是在两个转换结果之间互相对照。[6]

> **一句话听懂**：导入器把 URDF/MJCF 转成 USD，但转换有损；导入后按关节轴线与正负方向、限位、惯量参数、碰撞网格、执行器增益逐项核对，基准是官方源文件而不是两个转换结果。

### 传感器与渲染

Isaac Sim 的相机走 RTX 光线追踪渲染，能输出 RGB、深度、分割和光流，画质足以做 Sim2Real 的视觉训练；接触传感器和 IMU 也由 GPU 并行计算。代价正是开头观察到的吞吐下降：渲染是 GPU 上最贵的环节，视觉在环训练常用平铺渲染（Tiled Rendering）把多个环境的相机画面合并成一次渲染调用，换取吞吐。[4]

> **一句话听懂**：相机用 RTX 光线追踪渲染，RGB、深度、分割和光流都能出；渲染是 GPU 上最贵的环节，开相机掉的吞吐要靠平铺渲染把多环境画面并成一次调用来补。

## Isaac Lab 的强化学习环境（Isaac Lab 侧）

### 把 MDP 拆成 Manager

**观测管理器（Observation Manager）**：拼装观测向量。

这套拆分的价值在于可组合：换一个奖励项、加一种随机化，只改配置不改框架。[3][4]

> **一句话听懂**：Isaac Lab 把 MDP 拆成五个 Manager——观测、动作、奖励、终止、事件；换奖励项或加随机化只改配置，不动框架。

### 并行训练

并行训练是 Lab 侧做的活：Isaac Lab 把物理仿真、渲染和策略前向都放在 GPU 上，数千个环境并行 rollout（一轮并行采样），省掉 CPU-GPU 之间的数据往返。[2] 开头“一晚上几千万步 vs 4096 环境”的差距就来自这里。算法侧，Isaac Lab 的强化学习训练默认用 PPO（Proximal Policy Optimization，近端策略优化）这类 on-policy 算法：环境数越多，单次策略更新之间能收集的样本越多，这也解释了为什么它和“单机跑几千万步”不是一个量级。

<IsaacLabManagerSnippet variant="ppo" />

> **一句话听懂**：并行训练的吞吐来自把物理、渲染和策略前向都放在 GPU 上、数千个环境一起 rollout；Isaac Lab 默认用 PPO 这类 on-policy 算法，环境数越多、单次更新之间的样本越多。

### 并行训练的代价与边界

并行训练的代价是 Lab 侧的工程权衡，集中在几项：

- **显存限制环境数与相机分辨率**：环境数、相机分辨率和场景复杂度共同吃显存，想加相机往往得砍环境数；
- **物理并行度受接触复杂度影响**：接触越多、约束越复杂，每个环境在 GPU 上的物理开销越高，实际并行度低于环境数的名义值；
- **为吞吐放松的物理参数就是 Sim2Sim 差异的来源**：并行训练常把接触求解迭代数一类参数调小以换吞吐，这使训练环境成为最“宽松”的仿真器，回到 MuJoCo 就容易暴露；
- **并行训练是非确定性的**：浮点归约顺序与调度让同一配置两次训练结果不同，复现靠固定随机种子并记录配置，而不是靠重跑；
- **版本要对齐**：上面这些配置片段固定在提交 `b0542fe`，而实际安装的 Isaac Lab 版本可能不同，具体 API、任务名与参数名以所安装版本为准（[4]）。

> **一句话听懂**：并行的代价是显存限制环境数与分辨率、物理并行度受接触复杂度牵制、为吞吐放松的接触求解参数本身成为 Sim2Sim 差异来源，而且训练非确定性；具体 API 以所安装版本为准。

## 什么时候用 Isaac、什么时候不用

| 需求 | 首选工具 | 理由 |
| --- | --- | --- |
| 单机精确接触仿真、部署前验证 | MuJoCo（6.2 节） | 接触模型成熟，API 轻量，与部署代码同源 |
| 大规模 RL 训练 | Isaac Lab | GPU 并行数千环境 |
| 视觉在环训练 | Isaac Sim/Lab | RTX 渲染与分割标注 |
| ROS 2 集成、传感器插件生态 | Gazebo/RViz 2（6.4 节） | 与 ROS 2 消息和 TF 原生衔接 |
| 运动学/动力学算法计算 | Pinocchio/Drake（6.5 节） | 库而非仿真器，嵌入自己的代码 |

门槛与成本也要算进来：Isaac 需要 NVIDIA GPU（RTX 系列，显存直接决定并行规模），装驱动、配 Omniverse/Isaac 环境与版本管理是一笔固定开销，启动比 CPU 仿真器慢得多；它不适合做部署验证——部署与验证应交给 6.2 节的 MuJoCo 与真机。

工具选择经常比算法选择更影响进度。一个常见误区是用并行训练环境做最终验证：吞吐优化的物理参数让训练环境本身成为最“宽松”的仿真器，验证应始终在与训练不同的环境里进行。

> **一句话听懂**：大规模训练和视觉在环选 Isaac，单机精确接触与部署验证留给 6.2 的 MuJoCo，ROS 2 集成留给 6.4 的 Gazebo；用 Isaac 的前提是有 NVIDIA RTX GPU，并接受安装、版本管理和启动的成本。
