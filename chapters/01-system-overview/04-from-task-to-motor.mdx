# 1.4 从一句话到电机：整机总图

## 先看一个现场问题

朋友来看你演示。你对机器人说：“把桌上那个红杯子拿过来。”几秒钟后，它转身、走过去、伸手、抓住、回来，把杯子放在你手上。

朋友问了一个很朴素的问题：

> “这句话是怎么变成电机转动的？中间到底经过了多少东西？”

你可能答得出“先感知、再决策、再控制”。可再往下问就会卡住：谁负责把“拿杯子”拆成“先走过去、再伸手”？谁决定步子往哪儿落？谁保证它不会抓空、抓空了又怎么办？这些问题的答案分散在本书六章里。**这一节先把它们拼成一张图**——后面每一节都会回到这张图，告诉你自己站在哪里。

## 术语：三个词

### 纵向功能链（Vertical Functional Chain）

从“用户的任务”到“电机的力矩”，信息自上而下穿过若干层，每层把上一层的目标翻译成更具体的指令。这条链是**纵向**的：上面的层决定“做什么”，下面的层决定“怎么动”。

### 横向基础设施（Horizontal Infrastructure）

有些东西不属于任何一层，但每一层都要用：中间件、计算平台、安全、数据与日志、仿真工具、配置与模型。它们是**横向**的——像一栋楼里的水电和网络，不构成楼层，可哪一层都离不开。

### 闭环频率（Loop Rate）

每一层都不是“算一次就结束”，而是按自己的节奏反复跑：采集 → 判断 → 动作 → 再采集。越靠近物理世界，闭环通常越快；越往上，越慢。

> **一句话听懂**：整台机器人是一条纵向功能链——任务、行为、运动、控制、驱动、机械，上面定目标，下面出力气；另外还有一组横向基础设施（ROS、算力、安全、数据、仿真、配置）像水电一样供着每一层。

## 人话：一张图看懂整台机器人

先看纵向链。读这张表的方法：**从左往右是“目标怎么被翻译下去”，从右往左是“状态怎么被汇报上来”**。

| 层 | 它回答的问题 | 输入 | 输出 | 典型频率 | 本书哪一节 |
| --- | --- | --- | --- | --- | --- |
| 任务与智能层 | 用户到底要什么？先做哪一步？ | 语言指令、世界状态、记忆 | 子任务、技能调用 | 0.1–1 Hz | 本节、5.6 的“长任务的分解” |
| 行为与技能层 | 这一步怎么做？做完了吗？ | 子任务、世界状态 | 子目标（位姿、抓取点、落脚点） | 1–10 Hz | 本节、5.6 |
| 运动与规划层 | 从当前位置怎么过去、怎么够到？ | 子目标、地图、机器人状态 | 轨迹、落脚点序列 | 10–100 Hz | 5.3、5.4 |
| 实时控制层 | 这一毫秒全身各关节出多大力？ | 轨迹、姿态、接触力 | 关节目标、力矩 | 200 Hz–1 kHz | 4.5、4.6 |
| 驱动与嵌入式层 | 怎么把力矩指令变成绕组电流？ | 关节指令 | 电流、力矩、状态回传 | 1–20 kHz（电流环） | 3.2、3.4、3.5 |
| 机械执行层 | 力如何变成身体运动和接触？ | 力矩 | 关节运动、接触力 | 物理世界（连续） | 2.1–2.4 |

再看反馈：传感器不是“只给感知用”，它们分别喂给不同的层。

| 传感器 | 提供什么 | 送到哪 | 典型频率 |
| --- | --- | --- | --- |
| 编码器 | 关节角、角速度 | 驱动器内部的电流／速度／位置环 | 与电流环同周期 |
| IMU | 姿态、角速度、加速度 | 状态估计 → 平衡与全身控制 | 200 Hz–1 kHz |
| 相机（RGB／深度） | 图像、深度 | 感知 → 世界状态 → 规划与抓取 | 10–30 Hz |
| 激光雷达 | 点云 | SLAM／定位 → 导航 | 10–20 Hz |
| 力／力矩、足底、触觉 | 接触力、滑移、接触状态 | 力控与阻抗、抓取判定、失败检测 | 100 Hz–1 kHz |

两条链合起来才是闭环：**目标往下走，状态往上走**。表里的频率是典型量级，随实现和硬件变化——第 4、5、6 章会给出各自的真实取值。

> **一句话听懂**：记住两句话就够了——目标从上往下翻译（任务→行为→运动→控制→驱动→机械），状态从下往上汇报（传感器→状态估计与感知→各层决策）；两条线一合，就是一台会自己动的机器人。

## 频率金字塔：越靠近物理世界，闭环越快

把频率竖着排，就得到一张金字塔：

~~~text
任务与智能层     0.1–1 Hz      想清楚“做什么”
行为与技能层     1–10 Hz       组织“先做什么、做完没有”
运动与规划层     10–100 Hz     算轨迹与落脚点
实时控制层       200 Hz–1 kHz  算这一毫秒出多大力
驱动与嵌入式层   1–20 kHz      电流环跟着指令走
~~~

为什么必须这样分？因为越往下，**出错越不可挽回**：上层可以“想了 200 毫秒再改主意”，下层如果晚 5 毫秒补上平衡力矩，机器人已经倒了。于是真实系统让每一层按自己的周期独立运行，上层慢、下层快，中间靠“目标 + 时间戳”衔接。

这解释了一个新手最常见的误解：VLA 每几百毫秒才推理一次，那这中间机器人是不是站着不动、在等它想？

不是。**上层慢，不等于整机停**：在 VLA 思考的那几百毫秒里，实时控制层已经跑了几十到几百个周期，一直在维持平衡、跟踪上一条轨迹；上层的输出只是给下层换了个新目标。反过来说，如果下层的保护逻辑也要等上层点头，机器人早就摔了。

> **一句话听懂**：频率金字塔的意思是——越靠近物理世界，闭环越快、越不能停；上层思考的时候，下层一直在跑，机器人不是“想一步、动一步”。

## 算法跑在哪里

频率不同，跑的地方也不同。这是**典型**分配，不同厂商的实现不一样：

| 计算单元 | 通常跑什么 | 大概频率 | 本书哪一节 |
| --- | --- | --- | --- |
| GPU／SoC | 视觉模型、VLA、WAM 推理 | 1–30 Hz | 5.2、5.6、5.7 |
| 工控机 CPU | ROS 2 节点、任务执行、运动规划 | 10–100 Hz | 5.3、6.1 |
| 实时 CPU／实时域 | 状态估计、全身控制、学习策略 | 200 Hz–1 kHz | 4.4、4.6、5.5 |
| 关节 MCU | 关节位置／速度环、电流环、故障保护 | 1–20 kHz | 3.2、3.5 |

它们之间靠总线连起来：

~~~text
相机／激光雷达 → GPU／SoC → 工控机 CPU → 实时 CPU → EtherCAT／CAN／Ethernet → 关节 MCU → 驱动器 → 电机
~~~

注意最后一段：**算法最终都要变成总线上的一帧数据**，由 MCU 按固定周期发给驱动器。所以“算法很聪明、但总线抖了一下”照样会出问题——这也是 [3.4 节](../03-electrical-embedded/04-real-time-communication-and-buses.mdx)要讲实时通信的原因。

> **一句话听懂**：算法不是飘在空中的——它在 GPU 上想、在 CPU 上排、在实时域里算控制、在 MCU 上出电流，中间靠总线串起来；越往右，周期越短、越硬实时。

## 两个闭环：在线运行与离线开发

新手最容易把两件事混在一起：机器人身上的闭环，和开发机上的闭环。

**在线运行闭环**（跑在机器人身上，每个频率各有一圈）：

~~~text
传感器 → 感知／状态估计 → 任务／规划／策略 → 安全过滤 → 控制器 → 驱动器 → 电机 → 环境 → 传感器 ↺
~~~

**离线开发闭环**（跑在开发机上，不跑在机器人身上）：

~~~text
遥操作／仿真／真机日志 → 数据集 → 训练 → 评测 → 导出部署 → 回到机器人 → 继续采集 ↺
~~~

分清这两个闭环，四个常见问题就有答案了：

- **真机运行时还会训练吗？** 不会。运行时只做推理，训练在离线侧。
- **奖励（reward）在真机上还存在吗？** 不存在。强化学习的奖励只出现在训练环境里。
- **Isaac Lab 部署时要跑吗？** 不用。它属于离线侧，用来并行训练和评测；机器人身上跑的是导出后的策略。
- **遥操作数据什么时候用？** 离线侧：采集 → 清洗 → 训练 → 评测，再部署回机器人。

> **一句话听懂**：机器人身上跑的是“感知→决策→控制”的在线闭环，只推理不训练；训练、仿真、评测都在离线闭环里，靠数据与部署把两边接起来。

## 用同一个例子走一遍

回到开头那句“把红杯子拿过来”：

| 阶段 | 谁负责 | 输入 | 输出 | 频率 |
| --- | --- | --- | --- | --- |
| 听懂 | 任务层（语言理解） | 语音／文字 | 目标：找到红杯子并拿起 | 0.1–1 Hz |
| 组织 | 任务层 + 技能层 | 目标、世界状态 | 子任务：走到桌前 → 抓取 → 抬起 | 0.1–10 Hz |
| 过去 | 导航（定位 → 全局 → 局部 → 落脚） | 地图、当前位姿 | 落脚点序列／速度指令 | 10–100 Hz |
| 够到 | 操作规划 | 杯子位姿、机器人状态 | 末端轨迹、抓取位姿 | 10–100 Hz |
| 拿住 | 实时控制（全身控制 + 力控） | 轨迹、接触力 | 关节目标／力矩 | 200 Hz–1 kHz |
| 出力 | 驱动与嵌入式 | 关节指令 | 电流、力矩 | 1–20 kHz |
| 没抓住怎么办 | 技能层判定 + 任务层决策 | 观察结果 | 重试／换视角／换抓取／换站姿／求助／安全停 | 1–10 Hz |

最后一行值得单独记住：**机器人不是“任务→动作→成功”**，而是“任务→动作→观察→判断成功了吗→不成功就换个办法”。失败检测与恢复不是附加功能，而是自主运行的一部分——第 5 章会展开怎么判定、怎么恢复，[3.6 节](../03-electrical-embedded/06-electrical-safety-and-protection.mdx)讲硬件侧的失败怎么保护。

## 横向基础设施：不产生动作，但没有它什么都跑不起来

| 基础设施 | 它做什么 | 本书哪一节 |
| --- | --- | --- |
| 中间件与软件架构 | 把算法变成进程与节点，用 Topic／Service 连起来（ROS 2） | 6.1 |
| 计算平台 | 决定哪段算法跑在哪块芯片上（上一节的表） | 3.5、6.1 |
| 安全 | 硬件保护（急停、过流、过温、超时）+ 运行时安全过滤（限位、碰撞、可行性、命令新鲜度） | 3.6 |
| 数据与日志 | 记录 → 回放 → 失败挖掘 → 数据集 → 下一轮训练 | 5.5、6.6 |
| 仿真与工具 | MuJoCo、Isaac Sim／Lab、Gazebo、RViz 2、Foxglove | 6.2–6.5 |
| 配置、模型与标定 | URDF／MJCF、参数、固件、版本 | 2.5、6.6 |

这里要纠正一个很常见的直觉：**ROS 2 不是“大脑下面的一层”**。它不在动作链上，而是横向的软件基础设施——大脑、小脑、感知、仿真都在用它。把它当成楼层，就会出现“ROS 在控制之上还是之下”这种没有答案的问题。

## 上下游：这张图怎么用

- **读每一节时问一句**：它在这张图的哪一格？上游给它什么，它交出什么？（1.3 的“一条指令的旅程”是这条链的 G1 版本）
- **听到陌生词时先归类**：它是纵向链上某一层的模块，还是横向基础设施？
- **看演示时多问一句**：这段视频里是哪一层在起作用？换个对象、换个位置还成立吗？

## G1 落地

本书用 G1 把这条链落到具体名字上：`LowCmd` 逐关节携带目标位置、速度、前馈力矩与 `kp`／`kd`，`LowState` 回报电机状态与 IMU——**上层算法和真实电机之间隔着这两个消息**；官方低层示例的控制线程是 500 Hz（2 ms），落在金字塔的“实时控制层”；G1 的 URDF 里固定了 `d435_link` 与 `mid360_link`，对应相机与激光雷达的安装位姿。[5][6]

换成别的机器人（Unitree H1、Figure、Atlas、Optimus 等），具体实现会变：层数划分、频率取值、算力分配、消息格式都可能不同。**不变的是这条链本身**——总得有人理解任务、有人规划、有人算控制、有人出电流。学会看这张图，换一台机器人也知道该问什么。
