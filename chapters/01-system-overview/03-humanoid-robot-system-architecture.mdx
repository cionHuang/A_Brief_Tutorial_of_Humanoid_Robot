## 先看一个现场问题

朋友来看你演示。你对机器人说：“把桌上那个红杯子拿过来。”几秒钟后，它转身、走过去、伸手、抓住、回来，把杯子放在你手上。

朋友问了一个很朴素的问题：

> “这句话是怎么变成电机转动的？中间到底经过了多少东西？”

你可能答得出“先感知、再决策、再控制”。可再往下问就会卡住：谁负责把“拿红杯子”拆成“先走过去、再伸手”？谁决定步子往哪儿落？谁保证它不会抓空，抓空了又怎么办？

上一节把它拆开看了一遍——这一节回答这些部件**怎么一起工作**。

## 术语：三个词

### 纵向功能链（Vertical Functional Chain）

从“用户的任务”到“电机的力矩”，信息自上而下穿过若干层，每层把上一层给的目标翻译成更具体的指令。这条链是**纵向**的：上面的层决定“做什么”，下面的层决定“怎么动”。[1][2]

### 横向基础设施（Horizontal Infrastructure）

有些东西不属于任何一层，但每一层都要用：中间件、计算平台、安全、数据与日志、仿真工具、配置与模型。它们是**横向**的——像一栋楼里的水电和网络，不构成楼层，可哪一层都离不开。

### 闭环频率（Loop Rate）

每一层都不是“算一次就结束”，而是按自己的节奏反复跑：采集 → 判断 → 动作 → 再采集。越靠近物理世界，闭环通常越快；越往上，越慢。[3]

> **一句话听懂**：整台机器人是一条纵向功能链——任务、行为、运动、控制、驱动、机械，上面定目标，下面出力气；另外还有一组横向基础设施像水电一样供着每一层。

| 运动与规划层 | 从当前位置怎么过去、怎么够到 | 子目标、地图、机器人状态 → 轨迹、落脚点序列 | 10–100 Hz | 小脑 | 5.3、5.4 |

| 驱动与嵌入式层 | 控制周期能多短、延迟能多小 | 关节指令 → 电流、力矩、状态回传 | 1–20 kHz（电流环） | — | 3.2、3.4、3.5 |
| 机械执行层 | 身体能怎么动 | 力矩 → 关节运动、接触力 | 物理世界（连续） | 本体 | 2.1–2.4 |

“大脑”“小脑”这两列不是另一套架构，而是行业里为了交流方便用的**教学比喻**：高层任务与感知常被称为“大脑”，运动规划夹在中间，状态估计与实时控制是典型的“小脑”。它们之间没有一条能画在图纸上的边界——本书正式的分层只有上表这一套功能链。

表里没有单列“感知”：感知与状态估计不占层——它横在反馈链上，把传感器数据变成“世界什么样、我在哪”，再喂给上面各层（见 [4.4 节](../04-cerebellum-realtime-control/04-state-estimation.mdx)、[5.2 节](../05-brain-perception-planning-vla-wam/02-perception-system.md)）。

还有一条不占层、但处处相关的线：**电**从电池出发，经 BMS、配电板分配到每个模组——峰值功率、压降、热耗和急停切断路径都在这一条线上，属于驱动与嵌入式层，见 [3.1 节](../03-electrical-embedded/01-power-system.mdx)。

## 用红杯子走一遍

回到开头那句“把红杯子拿过来”：

| 阶段 | 谁负责 | 输入 | 输出 |
| --- | --- | --- | --- |
| 听懂 | 任务与智能层（语言理解） | 语音／文字 | 目标：找到红杯子并拿起 |
| 组织 | 任务层 + 技能层 | 目标、世界状态 | 子任务：走到桌前 → 抓取 → 抬起 |
| 过去 | 导航（定位 → 全局 → 局部 → 落脚） | 地图、当前位姿 | 落脚点序列／速度指令 |
| 够到 | 操作规划 | 杯子位姿、机器人状态 | 末端轨迹、抓取位姿 |
| 拿住 | 实时控制（全身控制 + 力控） | 轨迹、接触力 | 关节目标／力矩 |
| 出力 | 驱动与嵌入式 | 关节指令 | 电流、力矩 |
| 没抓住怎么办 | 技能层判定 + 任务层决策 | 观察结果 | 重试／换视角／换抓取／换站姿／求助／安全停 |

（“全身控制”指把全身关节放在一起解同一个问题，而不是每个关节各管各的；“力控”指控制接触时的力，而不是只盯位置。两者都在第 4 章展开。）

最后一行值得单独记住：**机器人不是“任务 → 动作 → 成功”**，而是“任务 → 动作 → 观察 → 判断成功了吗 → 不成功就换个办法”。失败检测与恢复不是附加功能，而是自主运行的一部分——怎么判定、怎么恢复见 [5.1 节](../05-brain-perception-planning-vla-wam/01-robot-learning-and-ai-terms.md)，硬件侧的失败保护见 [3.6 节](../03-electrical-embedded/06-electrical-safety-and-protection.mdx)。

传感器是这样回来的：相机每 30 毫秒左右给一帧图像，编码器与 IMU 以千赫兹量级汇报自身状态，足底力在接触瞬间跳变。它们汇进感知与状态估计，变成“杯子在哪、我站得稳不稳”，再喂回上面那几层。**没有这一步，机器人只是把预想的动作播一遍。**

## 为什么同时跑着好几个钟

总图上每层都标了频率，这不是凑数。真实机器人里，这些环**同时**在转。具体数字上面表里已经给过，这里只看数量级：

- 任务的推理可能只有几赫兹，一次思考几百毫秒；
- 视觉感知几十赫兹；
- 规划几十赫兹；
- 全身控制与学习策略数百赫兹；
- 关节伺服 500 Hz–1 kHz，电流环更高。

关键在于一句容易忽略的话：**高频控制不会等低频推理**。VLA 思考的那几百毫秒里，实时控制层已经跑了几十到几百个周期，一直在维持平衡、跟踪上一条轨迹；上层的输出只是给下层换了个新目标。反过来说，如果下层的保护逻辑也要等上层点头，机器人早就摔了。

> **一句话听懂**：机器人身上同时跑着好几个快慢不同的环——越靠近物理世界越快、越不能停；上层还在想，下层已经在动了。

## 算法跑在哪里

算法不是飘在空中的，它最终跑在真实计算硬件上。典型分工是这样：

| 硬件 | 通常跑什么 |
| --- | --- |
| GPU／SoC | 视觉模型、VLA 这类大模型的推理 |
| 工控机 CPU | 任务与行为、运动规划、中间件 |
| 实时 CPU | 状态估计、全身控制、学习策略 |
| 关节 MCU | 关节伺服与电流环 |

数据从相机进 GPU，从 GPU 到 CPU，再到实时域（必须按固定周期跑的那部分算力），最后经总线（EtherCAT／CAN／以太网）下发到每个关节的驱动器。不同机器人的划分并不相同——有的把控制也放在工控机上，有的用专用运动控制器。这里给的是典型架构，不是唯一答案。

## 旁边还有一组横向基础设施

| 基础设施 | 它做什么 | 本书 |
| --- | --- | --- |
| 中间件与软件架构 | 把算法变成一个个进程，用“话题”互相传消息（ROS 2）[6] | 6.1 |
| 计算平台 | 决定哪段算法跑在哪块芯片上（见上文“算法跑在哪里”） | 3.5 |
| 安全 | 硬件保护（急停、过流、过温、超时）；运行时安全过滤则是一道链上闸门，见下 | 3.6 |
| 数据与日志 | 记录 → 回放 → 失败挖掘 → 数据集 → 下一轮训练 | 5.5、6.6 |
| 仿真与工具 | MuJoCo、Isaac Sim／Lab、Gazebo、RViz 2、Foxglove | 6.2–6.5 |
| 配置、模型与标定 | URDF／MJCF、参数、固件、版本 | 2.5、6.6 |

“安全”要分两半看：急停、过流、过温、通信超时这些**硬件保护**横跨各层，属于基础设施；而**运行时安全过滤**（限位、碰撞、可行性、命令新鲜度——命令新鲜度就是“这条指令是不是已经太旧了”）是链上的一道闸门，挡在 AI／规划的输出和实时控制之间，所以它出现在上面的在线闭环里。

这里要纠正一个很常见的直觉：**ROS 2 不是“大脑下面的一层”**。它不在动作链上，而是横向的软件基础设施——上层的决策、下层的控制、感知和仿真都在用它。把它当成楼层，就会问出“ROS 在控制之上还是之下”这种没有答案的问题。

## 在线运行与离线开发

新手最容易把两件事混在一起：机器人身上的闭环，和开发机上的闭环。这里的“闭环”说的是**开发循环**，和 1.1 那个“感知—行动”环、以及前面说的“闭环频率”不是一回事——一个是任务环，一个是运行节奏，一个是开发流程。

**在线运行闭环**（跑在机器人身上，每个频率各有一圈）：传感器 → 感知与状态估计 → 规划／策略 → 安全过滤 → 控制 → 驱动 → 电机 → 环境 → 传感器。

**离线开发闭环**（跑在开发机上，不跑在机器人身上）：遥操作／仿真／真机日志 → 数据集 → 训练 → 评测 → 部署 → 回到机器人继续采集。

分清这两个环，几个常见问题自然就有答案了：真机运行时**不训练**，也没有 reward；Isaac Lab 这类仿真器只在离线侧出现；遥操作数据只在离线侧被消费。

> **一句话听懂**：机器人身上跑的是“感知→决策→控制”的在线闭环，只推理不训练；训练、仿真、评测都在离线闭环里，靠数据与部署把两边接起来。
