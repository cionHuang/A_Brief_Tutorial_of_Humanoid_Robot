## 从一次演示说起

你对机器人说：“把桌上那个红杯子拿过来。”几秒钟后，它转身、走过去、伸手、抓住、回来，把杯子放在你手上。

> “这句话是怎么变成电机转动的？中间到底经过了多少东西？”

你可能答得出“先感知、再决策、再控制”。可再往下问就会卡住：谁负责把“拿红杯子”拆成“先走过去、再伸手”？谁决定步子往哪儿落？谁保证它不会抓空，抓空了又怎么办？

这一节我们回答这些部件**怎么一起工作**。

## 从任务到动作

机器人会把一个高层目标逐步翻译成更具体的指令：从“用户想完成什么”，到“机器人采取什么行为”，再到“身体如何运动”，最后落实为电机和执行器的力矩。信息沿着这条链自上而下传递：上层决定**做什么**，下层决定**怎么做**。[1][2]

这条目标逐步具体化、指令逐级下发的路径称为**纵向功能链**（Vertical Functional Chain）。它由六个按职责分工、上下衔接的功能层组成。下面把“拿红杯子”放进这条纵向功能链中。实际系统可以合并或拆分模块，这里的划分用于说明职责和接口。[1][2]

| 功能层 | 在拿杯子时负责什么 | 向下一层输出 | 典型频率 |
| - | - | - | - |
| 任务与智能层 | 理解用户想拿哪个杯子、送到哪里 | 任务目标与子任务 | 0.1–1 Hz |
| 行为与技能层 | 组织走近、抓取、送回的步骤，检查每步是否完成 | 当前技能及其目标 | 1–10 Hz |
| 运动与规划层 | 规划绕障路线、落脚点和手靠近杯子的路径 | 运动轨迹与落脚点序列 | 10–100 Hz |
| 实时控制层 | 根据身体状态跟踪轨迹，在伸手时维持平衡 | 关节目标或力矩 | 200 Hz–1 kHz |
| 驱动与嵌入式层 | 将关节命令转换成电机电流 | 电流与力矩 | 1–20 kHz（电流环） |
| 机械执行层 | 让身体运动，脚与地面、手与杯子发生接触 | 身体运动与接触力 | 物理过程连续发生 |

表中的频率是一个估计值，用于比较各功能层的运行节奏；具体数值会随任务、硬件和实现方式变化。纵向功能链强调的正是：目标从上层逐步具体化为下层可执行的命令，同时状态和反馈沿相反方向返回上层。

## 用反馈修正动作

机器人执行动作时，需要持续了解环境和自身状态：杯子的位置、手是否抓住了它、身体是否保持平衡。相机、编码器和 IMU 的测量经过感知与状态估计后，供规划、控制和任务模块使用。

如果手已走完预定轨迹，但未能完成预期操作，行为与技能层就会识别执行失败并决定是否重试；必要时，任务层还要调整安排或请求帮助。动作后的观察会影响下一步决策，这就形成了**闭环**（Closed Loop）。

各层按不同的节奏更新反馈，完成反馈与修正的频率称为**闭环频率**（Loop Rate）。规划还在计算新轨迹时，控制层需要按自己的周期跟踪当前目标、维持平衡[3]，这也是机器人这种实时系统的一个特性——**高频控制不会等低频推理**。

感知与状态估计分别在 [5.2 节](../05-brain-perception-planning-vla-wam/02-perception-system.mdx)和 [4.4 节](../04-cerebellum-realtime-control/04-state-estimation.mdx)展开；任务中的失败检测与恢复见 [5.1 节](../05-brain-perception-planning-vla-wam/01-robot-learning-and-ai-terms.mdx)。

## 各层共用的基础设施

上面的分工要运行起来，还需要模块之间能传递消息、有足够的计算资源，并且能记录和处理异常。这些被各层共同使用的资源与机制，称为**横向基础设施**（Horizontal Infrastructure）。

| 基础设施 | 作用 |
| --- | --- |
| 中间件与软件架构 | 在模块之间传递消息。ROS 2 是一种常用的软件基础设施。[4] |
| 计算平台 | 安排视觉推理、规划、实时控制分别使用哪些计算资源。 |
| 安全 | 提供急停、过流、过温、通信超时等保护，并在命令执行前检查限位、碰撞风险和指令是否过期。 |
| 数据与日志 | 保存运行过程，支持回放、故障分析和后续训练。 |
| 仿真与工具 | 在测试和开发中验证模型、算法与系统行为。 |
| 配置、模型与标定 | 保存机器人结构、参数和版本，让各模块使用一致的模型与约定。 |

计算资源可以这样分工：视觉推理使用 GPU，任务与规划在工控机 CPU 上运行，实时控制使用满足周期要求的 CPU，关节侧的微控制器（MCU）执行伺服。带有 GPU 的片上系统（SoC）也可以承担视觉推理。不同功能可以共用硬件，功能层与芯片并非一一对应。

以 ROS 2 为例，它帮助模块交换消息，而消息里的单位、坐标系、时间戳和更新频率仍需要双方约定。[4] 因此，ROS 2 可以同时服务于规划、控制和感知，它在图中横向连接各层。安全也要看具体位置：急停等硬件保护横跨系统，运行时安全检查则是命令执行路径中的检查环节。
